API Recorder

Settings & recorded scenarios

Record XHR/fetch responses once, then replay them per tab without touching the server. Everything below applies to every tab that the extension runs on.

!

How it works

  • Records only XHR and fetch traffic, using the Chrome debugger API.
  • Each request is keyed by method + normalized URL + exact request body, so the same endpoint with a different body is stored as a separate recording.
  • GraphQL-looking requests (URL or body) are skipped and always hit the real network.
  • Recording and replay run only on the sites listed below.
  • If no exact recording matches, smart fallback matching replays the only recording for the same URL (or same path) when unambiguous. Requests that still go live are explained in the popup.
  • The popup lists only scenarios that recorded requests on the current tab's host (toggle to see all).
  • Scenarios can be exported (individually or all at once) to a JSON file and imported on another profile — single or bulk files — keeping replay and per-body matching intact.
  • Recorded payloads can be edited per request from the Scenarios section; the original body is kept so you can restore it.
  • Live mode sends every request to the real network without touching recordings.
  • Sessions are per tab. One tab can record while another replays.

      Troubleshooting

      Replay still sends requests to the real network?

      • Open the extension popup while replaying: the Session card lists every request that stayed live and why.
      • Compare the recorded URLs under “View requests” with the live requests in the browser DevTools network panel.
      • If the request body or query string differs from the recording, keep “Smart fallback matching” enabled in Settings.
      • Reload the unpacked extension after updating the source code: chrome://extensions → Reload.
      Includes settings, allowed sites, recorded request signatures and live-pass diagnostics.

      Limits & warnings

      • Deleting a scenario permanently deletes its recorded data. Responses stored for it are removed and cannot be recovered.
      • DevTools cannot be open on a tab while recording or replaying it. Chrome allows only one debugger client per tab, so close DevTools on the page before starting a session.
      • If you navigate outside the added sites, the session stops. Recordings captured so far are kept.
      • Recording is skipped for request bodies that are too large to key reliably, and for responses above the size limit set in Settings.
      • Only text payloads can be edited. Binary responses are read-only in the editor. Edits are stored locally and replay immediately; Restore original brings back the recorded bytes.
      • Deleting a recorded request is permanent — the trash button next to Edit always asks for an explicit confirmation first, and the scenario's count and host list update afterwards.
